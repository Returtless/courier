# 🚚 Courier Route Optimization Bot

Telegram бот для оптимизации маршрутов доставки с учетом пробок в реальном времени, временных интервалов доставки и управления заказами.

## ✨ Возможности

- 📍 **Оптимизация маршрутов**: OSRM основной провайдер маршрутизации (duration без пробок), геокодинг через Yandex/2GIS
- ⏰ **Управление временными окнами** доставки
- 🕐 **Ручное управление временем** - установка точного времени звонка и прибытия для любого заказа с защитой от перезаписи при реоптимизации
- 📞 **Автоматические уведомления** о звонках с кнопками подтверждения/отклонения
- 🔄 **Мониторинг пробок** в реальном времени
- ⚙️ **Персональные настройки** - каждый пользователь может настроить параметры работы под себя
- 💾 **База данных** с привязкой к пользователю и дате
- 🗑️ **Сброс данных** за текущий день
- ✅ **Отметка доставленных** заказов
- 🗺️ **Кликабельные ссылки** на маршруты и точки в 2GIS и Яндекс Картах
- 📱 **Удобный интерфейс** с кнопками для всех действий
- 🔍 **Быстрый поиск** заказов по номеру
- 📋 **Информативные кнопки** заказов с полной информацией
- 💬 **Система звонков** с повторными попытками (настраиваемое количество)
- 🗄️ **Кэширование** геокодирования и маршрутов для минимизации API запросов
- 📊 **Структурированное хранение** данных маршрутов и звонков
- 🏢 **Поддержка подъездов и квартир** для точного построения маршрутов
- 👥 **Многопользовательский режим** - несколько курьеров могут работать одновременно, каждый видит только свои заказы и маршруты
- 📲 **Автоматический импорт заказов** - импорт из веб-приложения ШефМаркет через встроенный браузер (Playwright)
- 🔐 **Безопасное хранение** учетных данных с шифрованием (Fernet)
- 🧪 **46 unit-тестов** - автоматическое тестирование критических компонентов

## 🛠️ Технологии

- **Python 3.11+**
- **pyTelegramBotAPI** - Telegram Bot API
- **SQLAlchemy** - ORM для базы данных
- **Alembic** - автоматические миграции базы данных
- **OSRM** - основной провайдер маршрутизации (duration без пробок)
- **Yandex Maps API** - открытый геокодинг (приоритет), резервный вариант
- **2GIS API** - открытый геокодинг/заглушки для routing “на будущее”
- **Geopy** - fallback для геокодирования
- **OR-Tools** - оптимизация маршрутов (VRP/TSP)
- **PostgreSQL/SQLite** - база данных
- **Playwright** - автоматизация браузера для импорта заказов из веб-приложений
- **Cryptography (Fernet)** - шифрование учетных данных пользователей

## 🧭 Структура проекта (для других AI-агентов)

Этот репозиторий содержит 2 части:

1) **Python-бэкенд Telegram-бота** (оптимизация маршрутов, геокодинг/маршрутизация, БД, уведомления).
2) **Android-клиент** (Jetpack Compose UI + Kotlin-оптимизатор маршрута с parity-логикой, без встроенного Python).

### Корень репозитория
- `main.py` — точка входа Telegram-бота.
- `src/` — основная логика Python (бот, сервисы, оптимизация, маршрутизация, API).
- `android/` — Android-приложение (UI, навигация, `KotlinOptimizer`).
- `alembic/` и `alembic.ini` — миграции БД.
- `docker-compose.yml`, `Dockerfile` — контейнеризация бэкенда.
- `docs/` — планы/документы по архитектуре и тестированию.
- `tests/` — unit/integration тесты.

### Python-бэкенд: `src/` (что где лежит)
- `[src/bot/]` — Telegram-слой:
  - handlers и сценарии взаимодействия с пользователем (заказы, маршрут, звонки).
  - вызывает сервисы оптимизации/репозитории.
- `[src/api/]` — HTTP API (FastAPI), маршруты и DTO/схемы.
- `[src/application/]` — “сборка” приложения и orchestration (контейнер зависимостей, application services).
- `[src/models/]` — модели данных (SQLAlchemy + Pydantic), включая Order/Route/CallStatus и кеши.
- `[src/database/]` — подключение к БД и Session lifecycle.
- `[src/repositories/]` — работа с БД на уровне репозиториев (OrdersDao/RoutesDao/CallStatusDao и т.п.).
- `[src/services/]` — бизнес-логика:
  - `[src/services/maps_service.py]` — геокодинг + построение маршрутов:
    - геокодинг: сначала **Yandex**, затем **2GIS**, fallback на geopy.
    - routing: **OSRM основной** (duration без пробок); 2GIS/Yandex routing оставлены как заглушки “на будущее”; общий fallback — haversine + средняя скорость.
  - `[src/services/route_optimizer.py]` — матрицы расстояний/времени + оптимизация VRP через OR-Tools.
  - `[src/services/route_optimizer_genetic.py]` — альтернативный/генетический оптимизатор (используется в гибридных пайплайнах).
  - `[src/services/call_notifier*.py]`, `[src/services/traffic_monitor*.py]` — уведомления и мониторинг (в зависимости от конфигурации).
- `[src/utils/]` — утилиты: форматирование, обработка ошибок, message_utils.

### Android-клиент: `android/app/`
- `android/app/src/main/java/com/courierplanning/`
  - `ui/screens/` — экраны:
    - `OrdersScreen` (список заказов + переход к импорту/настройкам),
    - `ImportTextScreen` (импорт заказов текстом),
    - `RouteScreen` (построение маршрута через Kotlin),
    - `CallsScreen` (логика звонков и повторов),
    - `SettingsScreen` (время/координаты старта и параметры маршрута).
  - `optimizer/KotlinOptimizer.kt` — JSON in/out как у бывшего `optimizer_bridge`: кластеризация + матрица (haversine при пустой `route_matrix`) + оптимизация.
  - `settings/StartLocationPrefs.kt` — хранение стартовых координат/времени в SharedPreferences.
  - `AppServices.kt` — инициализация Room DB и репозитория статусов звонков.
  - `data/db/` — Room: заказы, маршрут, настройки, статусы звонков, **`geocode_cache`** (кэш геокода как у бота).
    - Версия БД **2**, миграция **`MIGRATION_1_2`**: создаёт таблицу `geocode_cache`, при отсутствии колонки добавляет `orders.gis_id` (проверка через `PRAGMA table_info`).
    - `CourierApplication` вызывает `AppServices.init`; в `AndroidManifest.xml` укажите `android:name=".CourierApplication"` (или вызовите `AppServices.init` из своего `Application`).
    - `RouteScreen` передаёт в `KotlinOptimizer.optimizeRouteJson` реализацию **`RoomGeocodeCacheStore`** и обновляет координаты/`gis_id` заказа после геокода.
- `android/app/build.gradle.kts`
  - `buildConfigField` для ключей `YANDEX_MAPS_API_KEY`/`TWO_GIS_API_KEY` (на будущее для сетевых карт; текущий Kotlin-путь при пустой матрице использует haversine).
  - для Room KSP на Windows временная директория SQLite задаётся в начале скрипта (`%TEMP%/courier-room-sqlite-ksp`), см. комментарий в `build.gradle.kts`.

### Сквозной поток “Заказы -> Маршрут -> Звонки”
1. `ImportTextScreen` парсит текст заказов в entities (Room).
2. `RouteScreen` собирает payload (start time/координаты/окна) и вызывает `KotlinOptimizer.optimizeRouteJson`.
3. Оптимизатор строит синтетическую матрицу (haversine) и считает маршрут на устройстве (parity-пайплайн в `routeopt/`). Для эталонных сценариев см. `parity_fixtures/` и `tools/export_optimizer_golden.py` на Python.
4. `RouteScreen` сохраняет маршрут в Room и создает `CallStatusEntity` по `callAdvanceMinutes`.
5. `CallsScreen` показывает статусы и управляет retry-логикой через `CallStatusRepository`.

## 📦 Установка

### Локальная установка

1. **Клонируйте репозиторий:**
```bash
git clone <repository-url>
cd courier
```

2. **Создайте виртуальное окружение:**
```bash
python -m venv venv
venv\Scripts\activate  # Windows
# или
source venv/bin/activate  # Linux/Mac
```

3. **Установите зависимости:**
```bash
pip install -r requirements.txt
```

4. **Настройте переменные окружения:**
```bash
cp env.example env
```

Отредактируйте файл `env`:
```env
# Telegram Bot Token (получите у @BotFather)
TELEGRAM_BOT_TOKEN=your_bot_token_here

# 2GIS API Key (получите на dev.2gis.com)
TWO_GIS_API_KEY=your_2gis_api_key_here

# Yandex Maps API Key (опционально, для резервного геокодирования)
YANDEX_MAPS_API_KEY=your_yandex_maps_key_here

# База данных
# SQLite (для разработки):
DATABASE_URL=sqlite:///./courier_bot.db
# PostgreSQL (для продакшена):
# DATABASE_URL=postgresql://courier:courier_password@localhost:5432/courier_db

# Ключ шифрования для учетных данных (сгенерируется автоматически если не указан)
ENCRYPTION_KEY=your_generated_fernet_key_here
```

**Генерация ENCRYPTION_KEY:**
```python
from cryptography.fernet import Fernet
print(Fernet.generate_key().decode())
```

5. **Запустите бота:**
```bash
python main.py
```

### Docker установка

#### Вариант 1: Использование готового образа из GitHub Container Registry

1. **Создайте файл `docker-compose.prod.yml`:**
```yaml
services:
  bot:
    image: ghcr.io/YOUR_USERNAME/courier:latest
    container_name: courier_bot
    restart: unless-stopped
    environment:
      - TZ=Europe/Moscow
      - TELEGRAM_BOT_TOKEN=${TELEGRAM_BOT_TOKEN}
      - YANDEX_MAPS_API_KEY=${YANDEX_MAPS_API_KEY}
      - TWO_GIS_API_KEY=${TWO_GIS_API_KEY}
      - DATABASE_URL=${DATABASE_URL}
      - ENCRYPTION_KEY=${ENCRYPTION_KEY}
      - LLM_MODEL_PATH=${LLM_MODEL_PATH:-models/gemma3-4b}
      - LLM_DEVICE=${LLM_DEVICE:-cpu}
    volumes:
      - ./data:/app/data
    depends_on:
      - postgres
    networks:
      - courier_network

  postgres:
    image: postgres:15-alpine
    container_name: courier_postgres
    restart: unless-stopped
    environment:
      POSTGRES_USER: ${POSTGRES_USER:-courier}
      POSTGRES_PASSWORD: ${POSTGRES_PASSWORD:-courier_password}
      POSTGRES_DB: ${POSTGRES_DB:-courier_db}
    volumes:
      - postgres_data:/var/lib/postgresql/data
    networks:
      - courier_network
    ports:
      - "5432:5432"

volumes:
  postgres_data:

networks:
  courier_network:
    driver: bridge
```

2. **Войдите в GitHub Container Registry:**
```bash
echo $GITHUB_TOKEN | docker login ghcr.io -u YOUR_USERNAME --password-stdin
# Или используйте Personal Access Token с правами read:packages
```

3. **Настройте переменные окружения в Portainer:**
   - Перейдите в раздел "Environment variables" вашего стека в Portainer
   - Добавьте все необходимые переменные (см. раздел "Переменные окружения" ниже)
   - Убедитесь, что `DATABASE_URL` указывает на PostgreSQL: `postgresql://courier:courier_password@postgres:5432/courier_db`

4. **Запустите через Docker Compose:**
```bash
docker-compose -f docker-compose.prod.yml up -d
```

### 📲 Автоматический импорт заказов из ШефМаркет

Бот может автоматически импортировать заказы из веб-приложения ШефМаркет, избавляя от необходимости делать множество скриншотов на смартфоне.

#### Первоначальная настройка:

1. **Сохраните учетные данные** (делается один раз):
```
/set_credentials ваш_логин ваш_пароль
```
Пример:
```
/set_credentials ivan@mail.ru mypassword123
```

🔒 **Безопасность:**
- Логин и пароль шифруются с помощью Fernet (симметричное шифрование)
- Хранятся в базе данных в зашифрованном виде
- Никогда не передаются никуда, кроме официального сайта ШефМаркет
- Сообщение с паролем автоматически удаляется после сохранения

2. **Импортируйте заказы** (выполняется каждый день):
```
/import_orders
```

Бот автоматически:
- 🌐 Откроет браузер (Chromium) на сервере
- 🔐 Авторизуется на сайте ШефМаркет
- 📋 Получит список заказов на сегодня
- 📄 Перейдет на страницу каждого заказа
- 📦 Извлечет все данные:
  - Номер заказа
  - Имя клиента
  - Телефон
  - Полный адрес (включая подъезд, квартиру, этаж, домофон)
  - Временное окно доставки
  - Комментарии (включая "Бесконтактная доставка")
- 💾 Сохранит все в базу данных
- 🗺️ Подготовит заказы для оптимизации маршрута

**После импорта** сразу используйте **▶️ Оптимизировать** для построения маршрута!

#### Управление учетными данными:

- **Обновить учетные данные:**
```
/set_credentials новый_логин новый_пароль
```

- **Удалить учетные данные:**
```
/delete_credentials
```

#### Примечания:
- Импорт выполняется в headless режиме (без GUI) на сервере
- Весь процесс занимает ~30-60 секунд в зависимости от количества заказов
- Бот автоматически пропускает уже импортированные заказы (по номеру заказа)
- Если структура сайта ШефМаркет изменится, селекторы могут потребовать обновления

### ⚙️ Настройки

Каждый пользователь может настроить параметры работы бота под свои нужды. Доступ к настройкам - через кнопку **⚙️ Настройки** в главном меню.

#### Доступные настройки:

##### 📞 Звонки:
- **Время звонка до приезда** (1-60 минут, по умолчанию: 10) - за сколько минут до прибытия на точку звонить клиенту
- **Интервал повторных звонков** (1-15 минут, по умолчанию: 2) - через сколько минут повторить звонок после отклонения
- **Максимум попыток дозвона** (1-10 раз, по умолчанию: 3) - сколько раз пытаться дозвониться до клиента

##### ⏱️ Время:
- **Время на точке** (1-60 минут, по умолчанию: 10) - сколько времени тратится на доставку одного заказа
- **Время на парковку** (0-30 минут, по умолчанию: 7) - время на парковку и подход к подъезду

##### 🚦 Мониторинг пробок:
- **Интервал проверки** (1-60 минут, по умолчанию: 5) - как часто проверять изменения в пробках
- **Порог уведомлений** (10-200%, по умолчанию: 50%) - при каком увеличении времени в пути отправлять уведомление

Все настройки можно сбросить к значениям по умолчанию кнопкой **🔄 Сбросить к умолчанию**.

### Редактирование заказов

1. Нажмите **ℹ️ Детали заказа**
2. Выберите заказ из списка кнопок (каждая кнопка содержит полную информацию о заказе)
   - Или введите номер заказа прямо в чат для быстрого доступа
3. Используйте кнопки для редактирования:
   - **📞 Телефон** - изменить номер телефона
   - **👤 ФИО** - изменить имя клиента
   - **💬 Комментарий** - изменить комментарий
   - **🏢 Подъезд** - добавить/изменить номер подъезда
   - **🚪 Квартира** - добавить/изменить номер квартиры
   - **🕐 Время доставки** - изменить временное окно доставки
   - **⏰ Время прибытия** - установить точное время прибытия (вручную)
   - **📞⏰ Время звонка** - установить точное время звонка (вручную)
   - **✅ Доставлен** - пометить заказ как доставленный

**Особенности:**
- Кнопки заказов показывают всю заполненную информацию (номер, время, имя, телефон, адрес, подъезд, квартира)
- Сразу видно, какие поля заполнены, а какие нет (❌ означает незаполненное поле)
- Подъезд автоматически добавляется к адресу для точного построения маршрута
- Можно ввести номер заказа в чат в любое время для быстрого доступа

### Ручное управление временем (NEW!)

Для любого заказа можно установить точное время прибытия или звонка вручную:

#### Установка времени звонка:
1. Выберите заказ → **📞⏰ Время звонка**
2. Введите время в формате `ЧЧ:ММ` (например, `12:50`)
3. Бот автоматически рассчитает время прибытия (время звонка + 40 минут)

#### Установка времени прибытия:
1. Выберите заказ → **⏰ Время прибытия**
2. Введите время в формате `ЧЧ:ММ` (например, `13:40`)
3. Бот автоматически рассчитает время звонка (время прибытия - 40 минут)

**Защита от перезаписи:**
- ✅ Ручно установленные времена **НЕ изменяются** при реоптимизации маршрута
- ✅ При добавлении новых заказов и реоптимизации, ручные времена остаются фиксированными
- ✅ Алгоритм оптимизации учитывает ручные времена как жесткие ограничения
- ✅ Маршрут строится с учетом фиксированных точек

**Независимые времена:**
- Можно установить только время звонка (прибытие рассчитается автоматически)
- Можно установить только время прибытия (звонок рассчитается автоматически)
- Можно установить оба времени независимо (например: звонок в 13:00, прибытие в 13:00)

### Точка старта

1. Нажмите **📍 Точка старта** в меню "Маршрут"
2. Выберите способ:
   - **📍 Геопозиция** - отправить текущее местоположение
   - **✍️ Адрес** - ввести адрес вручную
3. При вводе адреса бот автоматически определит координаты и покажет ссылку на карту для подтверждения
4. Укажите время начала маршрута в формате `ЧЧ:ММ` (например, `09:00`)
5. Можно изменить время старта через кнопку **⏰ Время старта**

### Оптимизация маршрута

1. Добавьте заказы
2. Установите точку старта
3. Нажмите **▶️ Оптимизировать** в меню "Маршрут"

**Процесс оптимизации:**
- Бот показывает прогресс в реальном времени
- Геокодирует все адреса (использует кэш для уже известных адресов)
- Определяет координаты точки старта (если еще не определены)
- Строит оптимальный маршрут через OSRM (без пробок); 2GIS/Yandex routing временно отключены (заглушки); fallback — расчет по расстоянию/скорости
- Учитывает временные окна доставки
- Рассчитывает время звонков (минимум 40 минут до доставки)
- Сохраняет координаты всех точек для последующих оптимизаций
- Создает записи о звонках для автоматических уведомлений

**Результат:**
- Оптимальный порядок доставки заказов
- Кликабельные ссылки на маршруты и точки
- Полный график звонков

## 🗺️ Работа с картами

- **OSRM** - основной сервис для построения маршрутов (duration без пробок)
- **Yandex Maps API** - приоритет для геокодирования
- **2GIS API** - используется для геокодирования (routing оставлен как заглушка “на будущее”)
- **Geopy** - fallback для геокодирования (OpenStreetMap)
- (Пробки) текущий режим использует duration без пробок (OSRM)
- **Кликабельные ссылки** на маршруты и точки в 2GIS и Яндекс Картах

## 📊 Оптимизация маршрутов

- **OR-Tools** - продвинутая оптимизация от Google
- **VRP (Vehicle Routing Problem)** - оптимизация для нескольких курьеров
- **TSP (Traveling Salesman Problem)** - оптимизация для одного курьера
- **Time Windows** - учет временных интервалов доставки
- **Traffic-aware** - пока режим без пробок (duration от OSRM); пробки планируются через routing провайдеры “на будущее”
- **Constraint optimization** - ограничения по времени и расстоянию
- **10 минут на доставку** - учитывается время парковки и подхода к клиенту

## 💾 База данных

Все данные хранятся в базе данных с привязкой к:
- **Пользователю** (Telegram user ID)
- **Дате** (заказы привязаны к конкретному дню)

### Структура БД:

- **orders** - заказы с полной информацией (номер, адрес, телефон, имя, комментарий, подъезд, квартира, время доставки, координаты, `manual_arrival_time`)
- **start_locations** - точки старта по датам (адрес, координаты, время старта)
- **route_data** - сохраненные маршруты и графики звонков (структурированные данные)
- **call_status** - статусы звонков (время, попытки, статус, комментарии, `is_manual`, `arrival_time`)
- **geocode_cache** - кэш геокодирования для минимизации API запросов
- **user_settings** - персональные настройки пользователей
- **credentials** - зашифрованные учетные данные для импорта

### Настройка доступа к образу

1. Перейдите в настройки репозитория → Packages
2. Выберите созданный пакет `courier`
3. Настройте видимость (public/private)
4. Для использования на сервере создайте Personal Access Token с правами `read:packages`

### Использование образа на сервере

Создайте файл `docker-compose.prod.yml`:
```yaml
services:
  bot:
    image: ghcr.io/YOUR_USERNAME/courier:latest
    container_name: courier_bot
    restart: unless-stopped
    environment:
      - TZ=Europe/Moscow
      - TELEGRAM_BOT_TOKEN=${TELEGRAM_BOT_TOKEN}
      - YANDEX_MAPS_API_KEY=${YANDEX_MAPS_API_KEY}
      - TWO_GIS_API_KEY=${TWO_GIS_API_KEY}
      - DATABASE_URL=${DATABASE_URL}
      - ENCRYPTION_KEY=${ENCRYPTION_KEY}
      - LLM_MODEL_PATH=${LLM_MODEL_PATH:-models/gemma3-4b}
      - LLM_DEVICE=${LLM_DEVICE:-cpu}
    volumes:
      - ./data:/app/data
    depends_on:
      - postgres
    networks:
      - courier_network

  postgres:
    image: postgres:15-alpine
    container_name: courier_postgres
    restart: unless-stopped
    environment:
      POSTGRES_USER: ${POSTGRES_USER:-courier}
      POSTGRES_PASSWORD: ${POSTGRES_PASSWORD:-courier_password}
      POSTGRES_DB: ${POSTGRES_DB:-courier_db}
    volumes:
      - postgres_data:/var/lib/postgresql/data
    networks:
      - courier_network
    ports:
      - "5432:5432"

volumes:
  postgres_data:

networks:
  courier_network:
    driver: bridge
```

**Настройте переменные окружения в Portainer:**
- Перейдите в раздел "Environment variables" стека
- Добавьте все необходимые переменные (см. раздел "Переменные окружения для Docker" выше)

Войдите в GitHub Container Registry:
```bash
echo $GITHUB_TOKEN | docker login ghcr.io -u YOUR_USERNAME --password-stdin
```

Запустите:
```bash
docker-compose -f docker-compose.prod.yml up -d
```
